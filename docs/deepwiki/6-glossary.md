This page provides definitions for the technical terms, domain concepts, and internal jargon used throughout the MiroFish codebase.

## Core Simulation Concepts

### The Five-Stage Lifecycle
The MiroFish workflow is divided into five distinct stages, transitioning from raw data to interactive simulation.
1.  **Graph Building**: Extracting "seeds" from documents and constructing a Knowledge Graph (GraphRAG) [README.md:88-88](https://github.com/666ghj/MiroFish/blob/1536a793/README.md#L88-L88).
2.  **Environment Setup**: Generating agent personas and configuring simulation parameters [README.md:89-89](https://github.com/666ghj/MiroFish/blob/1536a793/README.md#L89-L89).
3.  **Simulation Execution**: Parallel multi-agent interaction on digital twins of Twitter and Reddit [README.md:90-90](https://github.com/666ghj/MiroFish/blob/1536a793/README.md#L90-L90).
4.  **Report Generation**: The `ReportAgent` analyzes the simulation outcomes [README.md:91-91](https://github.com/666ghj/MiroFish/blob/1536a793/README.md#L91-L91).
5.  **Deep Interaction**: Direct chat with agents or the `ReportAgent` [README.md:92-92](https://github.com/666ghj/MiroFish/blob/1536a793/README.md#L92-L92).

### Seed Information
Raw input materials (PDF, TXT, MD) provided by the user that serve as the ground truth for the simulation. These are parsed and converted into a Knowledge Graph [README.md:29-31](https://github.com/666ghj/MiroFish/blob/1536a793/README.md#L29-L31).
*   **Code Pointer**: `FileParser` and `TextProcessor` in the backend service layer.

### Agent Persona (Profile)
A digital identity generated by the `OasisProfileGenerator`. It includes a `username`, `profession`, `bio`, and `interested_topics` [frontend/src/components/Step2EnvSetup.vue:92-109](https://github.com/666ghj/MiroFish/blob/1536a793/frontend/src/components/Step2EnvSetup.vue#L92-L109). These personas are mapped to OASIS-compatible formats (CSV for Twitter, JSON for Reddit) [backend/app/api/simulation.py:13-14](https://github.com/666ghj/MiroFish/blob/1536a793/backend/app/api/simulation.py#L13-L14).

## Technical Domain Terms

### GraphRAG (Graph Retrieval-Augmented Generation)
The architecture used to store and retrieve seed information. Unlike standard RAG which uses flat vector chunks, GraphRAG preserves relationships between entities (Nodes) and facts (Edges) [README.md:88-88](https://github.com/666ghj/MiroFish/blob/1536a793/README.md#L88-L88).
*   **Implementation**: Utilizes **Zep Cloud** as the graph store [README.md:125-128](https://github.com/666ghj/MiroFish/blob/1536a793/README.md#L125-L128).
*   **Key Service**: `ZepEntityReader` [backend/app/api/simulation.py:12-12](https://github.com/666ghj/MiroFish/blob/1536a793/backend/app/api/simulation.py#L12-L12).

### ReACT (Reasoning and Acting)
The cognitive pattern used by the `ReportAgent`. The agent follows a loop of **Thought -> Action (Tool Call) -> Observation (Tool Result) -> Final Answer** [backend/app/services/report_agent.py:7-9](https://github.com/666ghj/MiroFish/blob/1536a793/backend/app/services/report_agent.py#L7-L9).
*   **Logic**: `ReportLogger.log_react_thought` [backend/app/services/report_agent.py:152-165](https://github.com/666ghj/MiroFish/blob/1536a793/backend/app/services/report_agent.py#L152-L165) and `log_tool_call` [backend/app/services/report_agent.py:166-186](https://github.com/666ghj/MiroFish/blob/1536a793/backend/app/services/report_agent.py#L166-L186).

### IPC (Inter-Process Communication)
The mechanism used by the Flask backend to control the standalone OASIS simulation scripts.
*   **Command Flow**: The backend writes JSON commands to `ipc_commands/` and reads responses from `ipc_responses/` [backend/scripts/run_parallel_simulation.py:205-209](https://github.com/666ghj/MiroFish/blob/1536a793/backend/scripts/run_parallel_simulation.py#L205-L209).
*   **Handler**: `ParallelIPCHandler` [backend/scripts/run_parallel_simulation.py:217-245](https://github.com/666ghj/MiroFish/blob/1536a793/backend/scripts/run_parallel_simulation.py#L217-L245).

## Report Agent & Tools

The `ReportAgent` uses a specialized set of tools to query the Knowledge Graph after a simulation completes.

| Term | Definition | Code Pointer |
| :--- | :--- | :--- |
| **InsightForge** | A deep retrieval tool that generates sub-queries to find multi-dimensional semantic facts. | [backend/app/services/zep_tools.py:138-141](https://github.com/666ghj/MiroFish/blob/1536a793/backend/app/services/zep_tools.py#L138-L141) |
| **PanoramaSearch** | A broad search tool used to get a "full picture," including expired or historical facts. | [backend/app/services/zep_tools.py:214-229](https://github.com/666ghj/MiroFish/blob/1536a793/backend/app/services/zep_tools.py#L214-L229) |
| **QuickSearch** | A simple, fast semantic search for specific keywords. | [backend/app/services/zep_tools.py:8-9](https://github.com/666ghj/MiroFish/blob/1536a793/backend/app/services/zep_tools.py#L8-L9) |
| **InterviewSubAgent** | A tool that allows the Report Agent to "talk" to a specific agent persona to get their perspective. | [backend/app/api/simulation.py:22-43](https://github.com/666ghj/MiroFish/blob/1536a793/backend/app/api/simulation.py#L22-L43) |

## Jargon & Abbreviations

*   **Zep**: The long-term memory and GraphRAG provider (Zep Cloud) [README.md:125-128](https://github.com/666ghj/MiroFish/blob/1536a793/README.md#L125-L128).
*   **OASIS**: The underlying swarm intelligence engine that MiroFish extends for social simulation [README.md:193-193](https://github.com/666ghj/MiroFish/blob/1536a793/README.md#L193-L193).
*   **Episode**: A discrete unit of information (e.g., an agent's tweet) sent to Zep to update the graph [backend/app/services/zep_graph_memory_updater.py:34-40](https://github.com/666ghj/MiroFish/blob/1536a793/backend/app/services/zep_graph_memory_updater.py#L34-L40).
*   **JSONL**: JSON Lines format used for `actions.jsonl` and `agent_log.jsonl` to allow streaming and crash-resilient logging [backend/app/services/report_agent.py:39-41](https://github.com/666ghj/MiroFish/blob/1536a793/backend/app/services/report_agent.py#L39-L41).
*   **Dual-Platform**: Refers to the simultaneous simulation of Twitter and Reddit environments [backend/scripts/run_parallel_simulation.py:6-10](https://github.com/666ghj/MiroFish/blob/1536a793/backend/scripts/run_parallel_simulation.py#L6-L10).
*   **Simulation IPC**: The custom communication layer using file-based signaling for `run_parallel_simulation.py` control [backend/app/services/simulation_runner.py:24-24](https://github.com/666ghj/MiroFish/blob/1536a793/backend/app/services/simulation_runner.py#L24-L24).
